# Atrium 開発方針・意思決定ログ

原案（`atrium-v1-implementation-brief.md` / `atrium-spec.md`）からの**現行方針と、その背景・決定事項・未決事項**をまとめる。
運用上の要点は `CLAUDE.md`、本書は「なぜそうなったか／これからどうするか」。

最終更新: 2026-06-20

---

## 1. ビジョン（現行）
美術家・奥中章人の世界観に「入って巡る」フロントエンド完結の体験サイト（採用プレゼン用）。
**3Dの実寸の町を歩き回り、描画は“動く水彩画”として見える**——没入感（ゲーム的体験）と情報サイトの実用性を両立する。

## 2. 原案からの逸脱（決定済み）
| 項目 | 原案 | 現行 | 理由 |
|---|---|---|---|
| 世界モデル | 正四面体（ハブ＋3場所）の小さな抽象球 | 大きな実寸の球(R≒60)＋歩ける小さな町。場所は町のランドマーク | 抽象配置がイメージと違った。歩ける町の方が「世界に入る」体験に合う |
| 操作 | タップで移動、球が回り込む | WASD/スティックで移動＋ドラッグで視点（3人称オービット） | 方向転換ができる定石の操作が必要 |
| 視点 | 没入のみ・中央固定・俯瞰なし | 3人称・自分でカメラを回す | 上記操作の結果。原則「没入のみ/俯瞰なし」は撤回 |
| スケール | 抽象（無単位） | 実寸（1単位≒1m）。アバター≒1.3m、建物≒5m | アバター⇄建物⇄道の実寸関係を求めた |
| アバター | 2Dの風(SVG)・中央固定 | 3Dで世界を移動（現状は仮の球） | 3D世界に合わせる。最終像は未確定 |
| 造形 | 手続き生成・水彩抽象 | Blender/CC0 の glTF を読み込み | 手続き生成はリアルさに欠ける |
| 絵柄の実現 | 水彩トーン（2D寄り） | **NPRで3Dを“水彩画”として描画** | 「3Dで動くが見た目は2D水彩」というユーザーの像 |
| ハブ | 四面体の1頂点 | 町の中心（広場） | 町モデルに合わせた起点。中身なしは同じ |
| 配信 | 未定 | GitHub Pages（Actions でビルド配信） | 目視確認の往復のため |

## 3. 維持する背骨（不変条件）
原案のうち以下は**そのまま有効**。崩さないこと。
- 入場/戻りの一本化 `enter()`/`returnToHub()`（タップ・メニュー・〔V2〕対話が同じ処理を呼ぶ）。
- 二重経路（巡る体験＋常時の文字メニュー）。
- V2継ぎ目：`intent+focus` 契約（`types.ts`）、対話UI枠（`AgentSlot`）。
- コンテンツ規約（公開情報のみ・事実創作なし・[サンプル]明示・抽象プレースホルダー・送信なし明示・提案デモ表示）。
- フロント完結 / LLM・backend・送信なし / メモリ状態。
- 軽量モバイル優先 / reduced-motion / 3D失敗時2D継続。
- 演出秒数枠（オープニング〜3秒、入り/戻り1〜2秒、オープニングは初回のみ）。
- 3場所と各場所固有の入り演出モチーフ（家＝カーテン／風船＝貫通／渦＝吸い込み）。

## 4. アート方針：3Dを“動く水彩画”に（NPR）
**ねらい**：形・動きは3D、見た目は2Dの水彩画。原案の「水彩・空気/水/光」を3Dで取り戻す。

**実現の積み木（Three.js）**
1. 平坦な陰影（トゥーン/フラット、彩度低め・コントラスト弱め）。
2. 紙の質感を全画面に乗算（post）。← 最重要。
3. 縁の滲み・顔料だまり（深度/法線エッジを柔らかく濃く）。「輪郭は曖昧」に合わせる。
4. 色の階調化＋にじみ。
5. 手描きの揺らぎ（画面/UVを微小ノイズで歪ませる）。
6. （任意・強め）Kuwaharaフィルタで絵画的ベタ塗り。重いのでモバイルは off。

**含意**
- glTF素材は**フォトリアル不要**。形を低〜中ポリで作り、マテリアルは簡素（水彩感はエンジン側で付与／マテリアル上書き）。
- モバイル：post処理はGPU負荷増。**品質ティア**（PCフル/スマホ軽量、Kuwaharaは上位のみ）で担保。
- 参考の系統：Okami（墨絵）、Gris、Sable。

**次の一手**：小さな「水彩レンダのスパイク」を現在の町に当てて検証 → 良ければ素材・アバターへ展開。

## 5. 素材（glTF）パイプライン
- 入手：CC0（Quaternius / Kenney / Poly Pizza）または Blender 自作。
- Blender規約：1単位=1m、原点=底面中心、直立、低〜中ポリ、簡素マテリアル、**GLB**書き出し（Apply Modifiers）。命名例 `cottage_a.glb`。
- 置き場：`public/models/`。ローポリGLBは git 直コミット可（大きくなれば LFS 相談）。
- コード：`drei useGLTF` + モデルレジストリ（名前→ファイル＋スケール/原点補正）。量産物は instancing。必要なら gltf-transform で Draco/KTX2。
- フォールバック：GLB未提供の種類は手続き生成のまま（混在OK＝1種ずつ差し替え）。
- ⚠️ 実行環境のegress制限により素材DLは不可。**ユーザーがアップロード**して受け渡す。

## 6. 未決事項（要決定）
- **アバターの最終像**：風の球体（シェーダー・抽象、テーマに合う）/ 3Dキャラ（Blender）。当面は仮の球。
- **水彩NPRの強度**：どこまで絵画的にするか（スパイクで見ながら）。モバイル品質ティアの線引き。
- **町の規模・内容**：建物の種類/数、道の通し方、ランドマークの配置。
- 風船（実作品の12mバルーン）・渦の最終表現（実作品資料に寄せるか）。

## 7. ロードマップ（現行）
- **いま**：移動・カメラ（完了）→ 水彩NPRスパイク → glTF差し替え → アバター確定 → 仕上げ（可読性・モバイル実機・演出の詰め）。
- **V2**（原案どおり）：対話エージェント（LLM＋backend）を `enter()` 経由で接続。`intent+focus` 契約と `AgentSlot` を使う。最初からAPIキー認証。

## 8. 受け入れ基準の扱い
原案 §9.1 の機能要件・コンテンツ・継ぎ目は**有効**。ただし質要件の「アバター中心・没入一貫（俯瞰なし）」は**3人称オービットへ更新**（撤回）。
「美しさ」の基準は**“動く水彩画”として成立しているか**に読み替える。
